# Vorssaint 代理模块设计

日期：2026-09-18。状态：第一至第三阶段及第五阶段功能已实现；第四阶段 TUN 实机验证按用户要求暂缓，完整 OpenVPN 分流适配仍待完成。具体交付及验收边界见第 10–12 节。

## 1. 目标与边界

在现有 macOS 14+ SwiftUI/AppKit 应用中新增可选「网络代理」功能，以独立 Mihomo 进程运行用户导入的本地 Stash YAML。第一版以实际附件 `fengheliang.yaml` 为兼容基线，支持同结构配置；OpenVPN 仍由现有客户端管理。

交付范围：本地配置导入与 YAML 编辑、策略组选择、延迟测试、规则查看与编辑、连接和流量、系统代理、LAN 共享、DNS、远程规则集缓存，以及经过共存验证的可选 TUN。

不纳入本版：节点订阅、完整 Stash 兼容、MitM、重写、脚本、Cron、云同步、OpenVPN 账号或隧道管理。远程 rule-providers 是当前配置的运行依赖，保留下载和更新。

采用 Vorssaint 原生界面，不引入 Clash Verge Rev 的 Tauri/React 界面。核心固定版本随应用发布，暂不提供独立自动升级；发布时记录版本、校验值、架构、对应源码和许可证材料。

## 2. 从真实配置得到的兼容基线

以下统计来自附件中未注释的配置文本；后续实现仍需 YAML 解析及固定版本核心校验，不能用文本统计代替语义验证。设计文件不保存节点地址、密码、UUID 或密钥。

| 项目 | 实际内容 | 设计处理 |
|---|---|---|
| 节点 | 6 个，2 个 SS、4 个 VLESS/Reality | 依据 type 解析，不能依据 vmess 开头的名称判断协议 |
| 策略组 | 7 个 select：Proxy、manual、Mox、Microsoft、Apple、MATCH、Hijacking | 动态生成界面，支持组引用和 DIRECT/REJECT |
| 规则 | 808 条，9 类 | 保持顺序，不能自动去重或排序 |
| 规则类型 | DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR、IP-CIDR6、PROCESS-NAME、RULE-SET、GEOIP、MATCH | 交给核心执行；导入阶段检查参数和引用 |
| rule-providers | 13 个 HTTP provider，domain/ipcidr/classical | 由核心管理内容与更新；UI 展示状态、缓存时间和失败原因 |
| DNS | redir-host、普通上游、DoH fallback、公司 nameserver-policy | 保留配置，重点验证公司解析 |
| 端口 | mixed 7890、controller 9090、DNS 53 | 启动预检占用；不能关闭其他程序来抢占 |
| 默认 | rule、warning、allow-lan=true | 导入预览明确显示实际运行设置 |
| 未出现 | tun、proxy-providers、HTTP 重写、脚本 | 不据旧截图扩展配置兼容范围 |

导入报告必须覆盖这些具体问题：

1. **8 处规则引用 `PROXY`，但定义的是 `Proxy`。** 对本附件提供 `PROXY → Proxy` 修复预览；只有大小写忽略后唯一匹配才可建议映射。用户应用修复后生成运行配置，不修改原件，不对所有标识符统一改大小写。
2. **`MATCH,DIRECT` 后还有 IP-CIDR 规则。** 显示不可达提示，保留原顺序；用户可以主动移到 MATCH 前。不能擅自将最终策略改成 Proxy。
3. **`152.136.138.142/24` 带主机位。** 提示其网络范围与 /32 的区别，按核心校验结果处理，不能猜测用户想要哪个范围。
4. **`MATCH` 策略组与 `MATCH,DIRECT` 规则不同。** 界面提示该组不控制当前最终规则；组名和规则类型不能混淆。
5. 重复规则、未引用组和 provider 仅提示，不删除。SS 项中的附加字段也需要核心验证，不能仅凭成功解析就声称兼容。
6. DNS 原值为 `0.0.0.0:53`。默认建议运行覆盖为 `127.0.0.1:1053`，在预览中说明它改变了 DNS 对外服务行为。需要 LAN DNS 服务时才显式选择原监听配置，并预检权限和冲突；LAN 代理共享与 LAN DNS 服务分成两个设置。

## 3. 界面与交互

入口放入功能中心「网络代理」，与已有「网络信息」并列。菜单栏展示紧凑卡片；复杂操作打开独立原生管理窗口。沿用现有字体、卡片、间距与多语言机制。

管理窗口建议初始 1040×720，最小 840×600。左侧约 164 点导航，右侧为工作区，顶部始终显示连接状态和启停按钮。

```text
┌ 网络代理 ───────────────────────────────────────────────────┐
│             fengheliang.yaml   ● 运行中        [停止代理]   │
│ 概览        [规则模式 ▾]  系统代理 开   增强模式 关          │
│ 代理                                                       │
│ 规则        上传速度        下载速度        活跃连接        │
│ 连接        ─────────── 实时流量趋势 ─────────────           │
│ 配置                                                       │
│ 设置        当前策略  Proxy → manual → 所选节点              │
│             公司网络  DNS 可达 / 路由待检测    [检测]        │
│             最近事件  配置已应用                            │
└────────────────────────────────────────────────────────────┘
```

| 页面 | 内容与主要操作 |
|---|---|
| 概览 | 启停、规则/全局/直连模式、系统代理/TUN 状态、当前配置、流量趋势、连接数、公司网络检测；公网 IP 按需查询并标注路径与时间 |
| 代理 | 左侧策略组列表，右侧节点列表；当前选择、延迟、失败原因；单节点/当前组测速，取消和并发上限；节点名称动态读取 |
| 规则 | 按原顺序显示编号、类型、内容、策略；搜索、增删改、移动；provider 规则单独只读查看；说明前序规则可能覆盖后序规则 |
| 连接 | 域名/IP、进程（可能缺失）、命中规则、代理链、流量；搜索、关闭指定连接；切换节点后提示已有连接可能仍用旧链路 |
| 配置 | 本地配置列表；原始 YAML、编辑草稿、有效配置；导入检查、差异预览、应用与回退；第一版不制作全字段表单编辑器 |
| 设置 | 端口、LAN、DNS、系统代理、TUN、启动行为、核心版本、日志与诊断 |

首次使用：导入文件 → 查看兼容报告及运行覆盖 → 修复阻断项 → 保存 → 点击启动。阻断项显示字段路径/行号；错误草稿可保存，但不替换正在运行的配置。

菜单栏提供紧凑卡片与完整快捷菜单；完整清单见第 9 节。关闭管理窗口或退出应用不停止已启动的代理；显式停止、禁用此功能必须走完整停止恢复流程。默认不开机自动接管网络。

## 4. 模块与仓库接入

```text
Proxy UI / Menu card
       ↓
ProxyService（单一状态入口）
  ├─ ProfileStore / ConfigCompiler / CompatibilityReport
  ├─ MihomoControllerClient（控制与事件流）
  ├─ CoreSupervisor（生命周期与健康检查）
  ├─ SystemProxyCoordinator（网络服务设置和恢复）
  └─ VPNCoexistenceMonitor（路由、DNS 与网络变化）
       ↓ 受限 XPC
ProxyHelper（特权操作、进程监管、异常清理）
       ↓
固定版本 Mihomo
```

建议新增 `Services/Proxy/`、`UI/Proxy/`、`UI/Settings/ProxySettings.swift`、`UI/MenuPanel/PanelProxyView.swift`、`Core/ProxyStrings.swift` 和独立 `Sources/ProxyHelper/`。复用 FeatureCatalog/FeatureRuntime 的可选功能生命周期和 AppDelegate 窗口入口；不让未启用功能提前实例化服务。

已有 NetworkInfoService 只复用适合的本机地址/展示能力，保持其按需公网查询约定。公司连通性监测由新模块负责；不能凭 utun 名称判定哪个接口属于 OpenVPN。

状态模型分开记录：核心状态、网络接管状态、配置修订、公司网络健康。核心启动成功不等于系统代理已生效，更不等于节点或公司网络可达。

核心状态：stopped → validating → starting → running → stopping → stopped；失败携带阶段和恢复结果。配置应用使用递增修订 ID 和串行协调，避免连续点击与旧异步结果覆盖新状态。

Helper 是独立职责，不扩展电池或风扇 Helper。仅接收启动固定核心、停止所属进程、应用白名单网络设置等结构化命令；验证调用方身份和文件归属，不提供任意命令执行。TUN 需要的权限和签名安装流程在技术验证阶段落实。

## 5. 配置与控制

数据分为三层：原始 YAML（只读留档）、编辑草稿及用户覆盖、编译后的运行 YAML。YAML 编辑是完整能力入口；规则 GUI 编辑的是草稿，应用前显示序列化差异，明确可能改变注释/格式。原始文件永远保留。

建议选用支持 YAML 的成熟 Swift 库，接入前验证映射、序列、行内对象、引号、重复键与错误定位；不使用正则表达式作为配置解析器。限制文档大小、别名展开和外部路径；不支持的行为字段阻断并解释，不能静默丢弃。

编译顺序：原始/草稿 → 已确认的兼容修复 → 用户设置 → 应用管理字段。应用管理字段包括本地 controller、随机鉴权 secret、受控数据路径。界面显示有效值和来源。

文件保存于应用专属 Application Support 目录，配置与日志使用仅当前用户可读权限。controller secret 保存在 Keychain；完整 YAML 包含的节点凭据仍以私有文件存储，不承诺全部已迁移到 Keychain。备份默认不包含这些敏感配置；显式导出时由用户选择。

控制 API 只监听回环地址并附带随机密钥。UI 使用核心接口读取代理/规则/连接、选择节点、测速、模式和配置；流量/日志使用事件流，断开后有上限退避。接口路径及参数以固定核心版本验证为准。[Mihomo API 文档](https://wiki.metacubex.one/api/)

应用配置事务：解析检查 → 引用检查 → 生成候选配置 → 核心配置校验 → 准备依赖 → 加载/重启 → 健康检查 → 标记为 last-good。失败恢复上一个有效版本及模式/策略选择。端口、DNS 监听或 TUN 变更允许受控重启，不承诺所有修改无损热加载。

provider 路径限定在配置自己的工作目录中。更新失败保留上次有效缓存；首次没有必要规则集或 GEO 数据时不接管系统流量，明确显示资源缺失。下载路径需避免“必须先使用尚未就绪的代理才能下载规则”的启动循环：先尝试可用直连缓存准备，无法完成则显示可重试错误。

## 6. 系统代理与 OpenVPN 共存

### 系统代理：默认路径

启动核心并确认本地监听及控制 API 就绪后，再修改所选网络服务的 HTTP/HTTPS/SOCKS 设置。默认只接管当前活动物理网络服务，记录服务 ID、原代理/PAC/绕过列表与本次写入值。切换 Wi-Fi/有线时重新协调。

公司域名经过 HTTP CONNECT 或远端解析的 SOCKS 请求进入 Mihomo 后，依照 nameserver-policy 解析并 DIRECT 出站；最终出站接口由系统路由决定。直接访问公司地址的应用仍依赖 macOS/OpenVPN 的解析与路由。**系统代理不覆盖所有 TCP/UDP，也不会把所有系统 DNS 查询送进 Mihomo。**

不把公司域名自动加入系统代理绕过列表；否则请求可能跳过 Mihomo 的公司 DNS policy。保留系统原有绕过项并在诊断中解释实际路径。不修改 OpenVPN 推送的 DNS 或默认路由。

停止时先恢复代理再停止核心。只恢复仍等于本模块写入值的字段，保留运行期间其他软件所作的修改，并提示冲突。接管日志需在变更前持久化；Helper 在核心异常退出、客户端失联时清理所属设置，下一次启动也执行恢复核对。正常功能禁用、卸载及显式停止使用同一清理入口；界面退出仅断开控制连接。

### 公司网络正确性

保留公司域名、公司 DNS 和现有 DIRECT 规则顺序。nameserver-policy 可优先于一般 DNS/fallback，但实际行为必须用固定核心验证，尤其是 fallback-filter 包含私网网段的组合。[Mihomo DNS 文档](https://wiki.metacubex.one/config/dns/)

检测分别给出：公司 DNS TCP/53 可达性、公司域名解析结果、目标 IP 路由接口、目标服务连通性。DNS 超时、缺路由和服务拒绝连接是不同错误。存在隧道不代表公司网络健康；无法确认时展示「待检测」。公司 DNS 不可达时，不自动改用公网 DNS 解析公司域名。

原配置中的 `121.36.94.175/32` 仅视作用户配置的绕过地址；是否为当前 VPN 服务端需要运行环境确认。DIRECT 意味着核心不使用代理节点，不能保证系统把请求送到 VPN。

### TUN：可选且单独验收

默认关闭；属于本设计完整交付的后续阶段。使用 Mihomo TUN 与受控 Helper，不默认引入 Network Extension。平台相关路由选项不能照搬 Linux；文档明确 auto-redirect 仅 Linux 支持，macOS 的局域网 DNS 劫持也有限制。[Mihomo TUN 文档](https://wiki.metacubex.one/config/inbound/tun/)

进入 TUN 前记录物理默认路由、现有 VPN 路由、公司 DNS 路径及代理服务器路径。公司私网、公司 DNS、已确认 VPN 服务端和必要本地网络不应被本模块 TUN 覆盖；候选排除配置必须在目标 macOS 与固定核心版本上验证。不能只填 DIRECT 或排除整个 utun 接口就宣称共存成功。

第一阶段 TUN 共存验证保留系统 DNS 配置，不开启通配 DNS 劫持；分别验证系统解析与核心解析。需要完整 DNS 接管时，单独设计可恢复的本地 DNS 路由，并验证公司 DNS 不被循环劫持；通过之前不得把此能力显示为可用。

监听网络/VPN 变化，重新核对路由。若出现路由争夺或默认出口变化，暂停自身 TUN、清理自身变更并显示原因；只有系统代理路径健康且原先已启用才保持该路径。不得删除其他 VPN 的路由，也不硬编码 utun 编号。IPv6、全隧道 OpenVPN 和 split tunnel 必须分别测试；DNS 的 ipv6=false 不等于关闭所有 IPv6 流量。

## 7. 性能与故障体验

页面可见时流量按约 1 秒刷新，连接列表限频更新；关闭页面后暂停非必要采样，保留生命周期监管。日志采用限大小轮转、内存有界队列，默认 warning；诊断导出脱敏，不自动附带完整 YAML。

核心退出最多有限次退避重试；反复失败停止接管并保留错误原因。端口冲突明确显示冲突端口及可选改端口操作；不杀死 Stash 或其他代理。切换模式和节点先发送请求，成功回读后再更新已生效状态，失败恢复显示。

测速结果是测试目标的响应延迟，不能等同于带宽或所有站点可访问。公司检测和公网 IP 检测均由用户主动触发；网络变化可以使结果失效，不自行发送用户未请求的外部探测。

## 8. 实施顺序与验收

| 阶段 | 交付 | 完成标准 |
|---|---|---|
| A 配置与核心验证 | YAML 解析、修复报告、固定核心适配、依赖缓存 | 脱敏样例解析正确；真实附件经明确修复后核心接受；无凭据进入仓库 |
| B 本地代理闭环 | 核心启停、系统代理恢复、原生 UI、组选择、测速 | SS/VLESS 实测；配置失败回退；进程异常退出后网络设置恢复 |
| C 配置管理与诊断 | YAML/规则编辑、provider 状态、连接、日志、公司检测 | 规则顺序保持；失效引用阻断；离线缓存启动；公司解析及直连路径通过 |
| D TUN 共存 | Helper、路由生命周期、冲突恢复 | VPN 前后启动、重连、休眠唤醒、网卡切换、IPv6 和全隧道组合通过 |

必要自动验证：引用大小写与组循环、MATCH 后规则、修复不修改原件、工作目录越界、错误候选不覆盖 last-good、并发启停串行化、系统设置只恢复自身写入字段、网络服务变化和 API 断线。

真实网络验收：OpenVPN 先开/后开、VPN 断开重连、系统代理/TUN 各自启停、Stash 占用端口、LAN 开关、公司 Git DNS 与 TCP 连接、外网代理、rule-provider 首次失败与缓存更新失败、退出/强制终止/重启恢复。配置校验通过不等于连通性通过。

截至 2026-09-18，分阶段交付与实测边界见第 10、11 节；设计表不能作为已完成验收清单。

截图中的品牌/第三方署名不作为功能复制。远程控制器入口按下表收敛为 Controller 设置及地址复制，不默认嵌入外部 Web 控制面板。

### 功能与行为

| 菜单项 | 子菜单或操作 | 状态与边界 |
|---|---|---|
| 状态与启停 | 核心状态、启动/停止代理 | 核心异常不能显示为运行；停止执行网络恢复 |
| 仪表盘 | 打开原生代理概览窗口 | 与配置管理窗口属于同一功能模块 |
| 出站模式 | 直连 / 规则 / 全局，当前项打勾 | 请求成功并回读后改变勾选，失败保留原状态 |
| 动态策略组 | 显示组名和当前选择；子菜单列出成员、当前勾选、已有延迟 | 按有效配置生成，不能硬编码这 7 个组；组成员显示为可选目标，不递归展开无限层级 |
| 策略组测速 | 测试当前组、在窗口管理该组 | 用户点击才测速；刷新数据时保持菜单焦点；切换不默认断开旧连接 |
| 活跃客户端 | 最多显示 5 个活跃应用/进程，上传与下载速率；点击查看该应用连接 | 用核心可提供的进程信息聚合，缺失时显示未知进程；不是整机所有网络流量 |
| 查看全部连接 | 打开连接页 | 不把长连接清单塞进菜单；无流量时显示空状态 |
| 系统代理 | 勾选开关 | 与设置页双向同步；核心未运行时显示需先启动 |
| 增强模式 | TUN 勾选开关 | 首次需要权限或 Helper 时打开设置引导，不假装已开启；第四阶段验收后可用 |
| 允许局域网访问 | LAN 勾选开关 | 显示实际有效值，与配置覆写一致；不同时开启 LAN DNS |
| Shell 命令 | 复制本机 HTTP/HTTPS/SOCKS 环境变量命令；复制取消命令；LAN 可用时选择指定 LAN 地址 | 使用当前有效端口；仅复制，不执行，不写入 shell 配置；地址不得用公网出口 IP 代替 |
| 登录时启动 | 控制 Vorssaint 应用自启动 | 复用应用现有登录启动设置，避免重复注册 |
| 随应用启动代理 | 独立的代理自启动偏好 | 与应用自启动区别展示；默认关闭 |
| 切换配置 | 本地配置列表，当前有效配置打勾 | 先校验再切换；失败继续使用旧配置；存在未应用草稿时打开配置页处理 |
| 重新加载配置 | 重新编译并加载当前已保存的配置及覆写 | 不覆盖未保存的编辑器草稿；失败回退，端口/TUN 变更可能需要受控重启 |
| 规则集与远程资源 | 打开资源页；工具子菜单可触发全部规则集更新 | 保留缓存失败策略，不包含节点订阅 |
| 工具 | 公司网络检测、更新规则集、查看日志、打开 Controller 设置、复制本地 Controller 地址 | 属于新设计，非从截图推断的 Stash 子菜单；不把 secret 放进 URL 或复制文本 |
| 设置与退出 | 打开代理设置、退出 Vorssaint | 「停止代理」只停止模块；「退出」关闭整个界面应用，已启动的代理继续在后台运行 |

Shell 命令示例（实际生成时使用有效地址和端口）：

```sh
export http_proxy='http://127.0.0.1:7890'
export https_proxy='http://127.0.0.1:7890'
export all_proxy='socks5h://127.0.0.1:7890'
```

取消命令为 `unset http_proxy https_proxy all_proxy`，仅撤销上述小写变量；不声称清除用户另行设置的所有代理。LAN 地址只列举本机实际可用的地址，IPv6 URL 使用方括号；LAN 关闭时不提供 LAN 复制选项。

### 交互与验收

- 菜单栏、设置页和管理窗口订阅同一有效状态；更新中显示进行中，不先行伪造勾选。

## 11. 第三、第四阶段实现与验收状态（2026-09-18）

### 第三阶段：配置管理

已增加原生配置工作台：本地配置重命名、复制、删除和导出；原件只读；独立 YAML 草稿与覆写；节点（SS/VLESS/Reality）、select 策略组、DNS 常用项、HTTP 规则源的图形编辑；规则搜索、编辑和顺序调整。图形编辑与 YAML 共用草稿，保留未编辑字段，写回采用合法 YAML 的 JSON 子集，因此会失去注释；公司 DNS policy 等复杂字段可通过 YAML 编辑。

无效草稿可以保存，但不能应用。应用前检查引用、生成差异、准备资源并调用固定核心校验。运行中的切换、重载和历史回退使用独立候选工作目录；启动健康检查成功后才提交版本与运行目录指针。失败恢复旧配置；应用中断通过写前日志恢复。每个配置保存最多 30 个历史版本，保留当前与最近健康版本；旧资源工作目录限量清理，配置版本独立保存。规则源缓存键包含 URL、行为和格式，避免编辑后误用旧资源。

菜单已接入运行时配置切换、重载及规则集更新。资源页显示核心返回的规则集状态、数量、时间，并提供单项或批量更新；不包含节点订阅。系统代理开关、出站模式及节点操作继续复用统一服务。

真实 Mihomo/Guardian 集成测试已通过：启动、无效草稿不影响运行配置、有效草稿应用、配置切换、重新加载、历史回退、操作取消、并发停止与停止后重启。测试使用脱敏临时配置和隔离端口，未设置系统代理。

### 第四阶段：已实现的基础设施

新增 SMAppService 特权网络助手，签名要求绑定相同证书与精确应用标识，并限制当前控制台用户连接。助手只创建 utun 和管理自有路由，不读取用户 YAML、节点凭据或启动核心。网卡描述符经 XPC FileHandle、私有 Unix socket 的 SCM_RIGHTS 交给普通用户 Guardian；Guardian 通过受限 posix_spawn 将 fd 3 交给普通用户 Mihomo。核心控制端口及凭据仍限本机。

路由管理采用显式排除、写前日志、写后回读及撤销；保留既有路由，仅删除与自有网卡身份匹配的路由。助手检查随机地址与网卡索引，避免仅凭 utun 编号误删其他 VPN。应用崩溃、连接失效、心跳超时和网络变化触发恢复；休眠前停止，不在唤醒后自动夺取路由。IPv4 与可选 IPv6 分开处理；默认不修改系统 DNS、不劫持 53 端口。IPv6 接管关闭不代表禁用 IPv6。

启动先验证核心 `/configs` 中 TUN 已启用且网卡名匹配，之后才添加接管路由。固定版本源码 `listener.ReCreateTun` 在失败时把启用状态置为 false；仅 API 可访问不足以作为 TUN 就绪判据。

公司诊断由用户点击触发，直接查询指定公司 DNS（TCP/53、A 记录），分别报告 DNS 路由、DNS 回答、目标路由与 TCP 端口连通性；不自动回退到公网 DNS，也不根据网卡名称猜测 VPN 产品。

### 第四阶段仍未完成的部分

1. **真实特权验收未完成**：当前会话没有管理员 sudo 授权。没有安装/注册新助手、创建真实 utun 或修改系统路由。SMAppService 注册、XPC 描述符跨权限交接、真实 TUN 收发、崩溃恢复、休眠/唤醒及 Wi-Fi 切换仍须在授权后的开发包中验收。
2. **OpenVPN 分流兼容尚未覆盖完整场景**：固定 Mihomo v1.19.31 的 `component/iface.ResolveInterfaceByAddr` 按网卡地址网段查找，而不是查询内核路由表。VPN 推送的远端子网可能不属于 VPN 网卡自身地址网段。当前预检会拒绝这种无法可靠绑定的场景，并提示继续使用系统代理；不能把“排除路由成功”解释为所有核心 DIRECT/DNS 请求都能走正确 VPN。后续需要独立完成出站绑定适配，并覆盖规则、全局、直连三种模式及 DNS。
3. **全隧道 VPN**：检测到 VPN 默认路由或两个半默认路由时不启用 TUN，以免争夺出口；不宣称全隧道共存已经支持。

## 12. 第五阶段功能交付（2026-09-18）

### 已实现

- 实时流量：基于 `/connections` 累计计数计算上传/下载速率，展示核心内存（独立 `/memory` 流）、连接数、本次核心累计流量与最近 60 个样本的趋势。内存接口首次占位零值显示为“—”，不会伪装成零占用。首次采样、计数器重置或长时间采样间断不制造流量尖峰；不是整机流量统计。
- 活跃客户端：按核心返回的进程路径/名称聚合，菜单卡片展示前 5 项；点击进入对应应用的连接筛选。缺失进程信息显示“未知进程”，使用通用图标。
- 连接管理：搜索进程/域名/IP/规则/策略链，查看协议、开始时间与累计流量；断开单条连接，确认后断开全部连接。连接展示上限 5000 条，超限明确提示；流量总计仍使用核心全量值。应用可能自动重连。
- 日志：认证 WebSocket 日志流、运行时级别设置、暂停、搜索、清空、导出；断流后 3 秒重试。内存最近 1000 条，待写队列最多 1000 条，高压时丢弃最旧待写条目；单条限制 8192 字符。串行磁盘写入，两份文件各不超过 512 KiB，文件 0600、目录 0700；下次启动读取历史缓存。系统退出前等待写入完成。
- 日志凭据保护：采集时隐藏配置中的密码/UUID/控制密钥等已知敏感值，并清除凭据形式、Bearer token 与 URL。日志仍可能包含域名/IP，界面明确提示；不将日志原文纳入诊断报告。
- 诊断：先生成可检查的 JSON 预览，再保存同一份内容。字段白名单只包含版本、系统版本、构建号、运行状态、端口和数量/流量统计，不包含 YAML、配置名、节点名、连接目标、凭据或日志正文。
- 快捷键：接入现有统一快捷键设置、冲突检查与录制期间暂停机制。新增打开代理工作台、运行中切换系统代理、重新加载配置三个操作，默认禁用；没有给 TUN 配置快捷键。
- 采样生命周期：原生窗口可见/遮挡/最小化/关闭事件驱动连接轮询，多个可见入口共享一个采样任务。窗口和菜单都不可见时暂停连接轮询；默认警告日志仍在后台限量采集。停止/重载清理旧任务与 WebSocket，旧核心响应不能写入新会话。

### 空配置崩溃修复（2026-09-18）

实际崩溃栈定位到 `ProxyStructuredEditor → ProxyConfigCompiler.document → VPYAMLToJSON → yaml_parser_set_input_string`。空 NSData 的 bytes 可能为 NULL，libyaml 会断言退出，无法通过 Swift `try?` 捕获。现已在 Objective-C 桥接入口拒绝零字节输入并返回 NSError；图形编辑器遇到空草稿直接显示空状态，未选择配置时提示先导入。

回归覆盖桥接直接调用与 Swift 文档解析的空数据、空白和仅注释输入，以及真实图形编辑视图的未导入/清空草稿渲染。开发构建指定持久的 Swift module 输出路径，避免增量编译复用不存在的临时模块路径；安装脚本自调用改为明确的绝对脚本路径。

## 2026-09-19：代理独立后台生命周期（替代原匿名管道退出清理方案）

- `VorssaintProxyGuardian` 通过捆绑的 `SMAppService` LaunchAgent 由 launchd 管理，开发版和正式版分别注册。后台服务启动不代表自动启动代理；原有“Vorssaint 启动时自动启动代理”设置保持独立。
- 界面通过仅当前用户可访问的 Unix 控制套接字发送有长度上限、超时和结构化回复的请求。控制连接断开、界面退出或被 SIGKILL 均不再停止核心。
- Guardian 持有 Mihomo 进程、系统代理助手与 TUN 助手的 XPC 连接和心跳。TUN 文件描述符直接由助手交给 Guardian，界面不再拥有网络租约。
- 界面重开先查询后台运行配置、配置标识、核心 PID 和控制凭据，并直接接管现有进程。不会执行恢复网络、重编译配置、重设策略选择或启动第二个核心。
- 正常退出等待正在执行的配置事务结束并保存日志，然后退出界面。未完成且失去界面的核心启动事务由后台在 120 秒后清理。
- 显式停止先恢复系统代理和 TUN 路由，再终止核心。助手失联、核心退出、连续健康检查失败时仍执行恢复；界面退出不再被当作故障。原有增强模式休眠前停止策略仍然保留。
- 首次启用需要 macOS 允许后台运行；用户注销结束用户级服务。不会默认增加开机自动连接。界面关闭期间不采集 UI 流量图与 UI 日志流。
- 根权限助手只接受当前控制台用户、同一签名证书下的应用或指定 Guardian 标识；不扩大为任意同团队可执行程序。
- 验证：真实核心测试覆盖控制连接断开、界面父进程 SIGKILL、同 PID 接管、显式停止以及无界面时检测核心崩溃；服务测试覆盖配置事务、取消、回退和重开。系统代理租约与 TUN 路由恢复继续由原有测试覆盖。

### 网络助手移除与启动授权修复

- 不再按应用构建版本在启动过程中自动注销、重新注册网络助手。注册仅由用户点击授权触发。
- 移除助手先保存关闭系统代理和 TUN 的设置；未安装时重复移除视为成功。
- 缺少助手时，系统代理/TUN 在启动前返回应用内提示；Guardian 也拒绝无助手的系统代理开启请求。普通核心仍可独立运行。
- 服务集成测试覆盖缺少助手时启动拒绝、重复移除、随后普通核心启动及配置事务回归。

### 退出时选择保留或关闭连接

- 网络代理仍运行时，退出应用弹窗提供保留连接并退出、关闭连接并退出、取消。退出判断等待启动或配置事务结束，并检查后台状态。
- 选择关闭时先等待核心停止及网络恢复；失败则显示原因并取消退出。选择保留时只断开界面，后台连接继续运行。
- 菜单栏更多菜单移除实时字幕开关、打开和关闭入口。

### 登录自动启动的临时失败重试

自动启动在网络不可用、物理网络服务暂缺或助手 XPC 暂时中断时，最多重试六次，等待间隔为 5、10、15、20、25、30 秒。每次失败先完成原有停止恢复；恢复失败则终止重试。授权、配置和端口冲突仍直接提示错误。手动停止取消当前启动及等待；错误原因和重试记录写入代理日志。

### TUN 切换前预检

运行中启用 TUN 时，先检查网络助手、节点/DNS 解析与现有 VPN 路由兼容性，预检失败保留当前核心及系统代理，显示并记录原因。通过后才停止旧核心进行切换；实际启动仍重复校验，避免网络状态变化导致误用旧结果。切换中失败继续恢复原模式并记录错误。

### TUN 与分流 VPN 共存及取消恢复（2026-09-21）

- 保留现有 VPN 路由，替换原网卡地址前缀匹配禁用策略；规则模式运行配置为公司目的网段生成显式 interface-name 直连出站，公司 DNS 数字地址同时绑定对应接口。原 YAML 和系统 DNS 不变。
- TUN 无用户 sniffer 配置时启用 HTTP/TLS/QUIC 域名识别，使现有域名规则能处理仅含 IP 的 TUN 流量。遵循 Mihomo 的 DIRECT 与 sniffer 配置语义：https://wiki.metacubex.one/config/proxies/direct/ 、https://wiki.metacubex.one/config/sniff/ 。
- 路由通过 PF_ROUTE 添加/删除，批次前核对冲突和归属、批次后回读，不再为每条路由启动 route 与 netstat。实机 475 条路由添加约 0.14–0.16 秒，停止清理约 0.11–0.29 秒。
- 启动/资源加载期间提供独立的关闭 TUN 并停止入口；取消切换不再自动重启旧模式。慢资源下载取消和紧急停止纳入回归。
- 实机隔离端口验证：OpenVPN 在线时 TUN 接管公网，IPv4 Google HTTP 200，公司 DNS 返回正确地址，公司服务直接及经核心均 HTTP 302，核心日志确认公司出口 utun4；测试后自动恢复并保留 Stash。
- IPv6 接管及 OpenVPN 重连后的自动重新接管尚未实机验证；路由变化仍按原机制暂停 TUN。无域名可识别的流量继续按原 IP/MATCH 规则执行，TUN 不会把原 DIRECT 兜底擅自改成代理。

### 精简菜单（2026-09-21）

菜单保留连接状态、当前节点/策略、分流模式、系统代理、TUN、自动启动代理、实时流量及连接/配置入口。节点入口沿当前策略组的选择链展示末端策略组，避免硬编码 `manual`，遇到环路停止遍历；实际切换仍由核心回读确认。完整策略组、连接、日志、诊断和终端命令放在工作台。菜单底部提供工作台入口，自动启动提示明确指应用启动时启动代理。启动中保留停止及关闭 TUN 的恢复入口，流量不可用时显示等待状态，停止后不显示旧流量。

菜单流量采用方案 C：默认折叠为“连接与流量”和活跃连接数，展开显示实时上下行速率、本次核心累计上下行流量及全部连接入口；移除菜单中的折线图，工作台图表保留。未采样显示等待数据，停止后不显示旧累计值。

节点测速默认在生成运行配置时启用 unified-delay（保留用户显式 false），由 Mihomo 对已建立连接发第二次 HEAD 请求计时。手动测试继续使用 Google HTTPS 204 地址；初次请求失败仍返回失败，第二次失败时核心可能回退首次耗时，不能把所有超时解释为显示问题。隔离实测 vmess5：Google HTTPS 931→157 ms，Apple HTTP 784→164 ms；对照核心关闭 DNS 模块且不接管系统网络，数值不等于 Stash 同时测量结果。

节点选择改为卡片原位展开，展开时收起模式、开关及流量配置区域，避免嵌套弹框裁切。测速不收起列表；节点切换等待核心回读成功后收起，失败保留列表和错误。停止及 TUN 恢复入口始终保留。
