# 独立电池管理

入口：设置 → 电池管理。电池状态图标独立于原有电源监控和 Keep Awake。

## 后台授权

先关闭 BatFi、AlDente 等其他充电控制器并在其中恢复系统充电，再点击“授权电池后台…”。
在系统设置的登录项与扩展中允许后台运行。定位另行授权，不自动请求。
无后台授权仍可查看电池信息和编辑配置，但不会宣称充电控制生效。

辅助程序是单独的 `battery-control` launch daemon，通过 SMAppService 注册，
XPC 双向校验证书指纹及精确 bundle identifier。支持项目原有的开发版签名，拒绝 ad-hoc 对端。
只暴露配置和有限命令，不提供任意 SMC key 写入接口。

## 功能及边界

- 功率分配采用双列胶囊：左侧输入、右侧输出。支持电源→电脑、电源→电脑+电池、
  电池→电脑、电源+电池→电脑；主动放电时按实际供电/电流显示，不依赖控制命令。
  小于 0.5 W 的电流功率变化按噪声处理，缺失数据保留“—”，切换时出现矛盾则提示等待采样。
  实时传感器可能不同步，不强行配平；额定功率仅放在说明中，不作为实时输入。
- 温度显示优先 AppleSmartBattery.VirtualTemperature / 100，与 BatFi 公开旧版相同；
  字段无效时回退 Temperature / 100，悬停显示来源及原始温度。
  温控保护仍读取原始 Temperature，不因显示口径调整而降低温控阈值。
- 菜单栏图标为自行绘制的轮廓/电量填充，内部用状态符号，隐藏百分比。
  充电后台故障写入提示文本，不再覆盖实际电池状态图标；未读到电量时显示问号。

- 上限 50–100%；恢复阈值可配置为低于上限 3/5/10 个百分点，不依赖“当前正在充电”。
- 临时充至 100%：满电或断开充电器后取消覆盖，回到自动管理。
- 主动放电：手动“使用电池运行”或超过上限时自动放电；达到上限、合盖、睡眠或断电时停止。
  单次最长 4 小时，触发时停止控制并要求手动重试。底线 20% 不允许主动放电。
- 高温暂停：可设 38/40/42°C，低于上限 3°C 后恢复；温度无效时暂停。
  临时充满不能绕过温控。不会通过额外负载人为升温进行测试。
- 睡眠：默认睡前暂停充电、醒后继续管理；也可选择睡前恢复系统自动充电。
  睡眠期间不持续采样温度或执行地点/时间规则；系统自动充电期间仍由系统实施硬件温控。
- 延缓睡眠：可分别对主动放电和未到目标的充电启用，仅使用独立的空闲睡眠 assertion。
  不阻止手动睡眠和合盖，不修改系统 pmset 设置。
- MagSafe：暂停时绿灯、主动放电开始时一次闪烁。检测 ACLC 接口，失败给出警告；
  接口存在不代表连接了带 LED 的 MagSafe，USB-C 看不到灯效。
- 自动化：规则可添加、编辑、删除、启停和调整优先级，支持星期、时间段、地点圆形区域。
  第一条匹配规则覆盖基础上限；跨午夜归属于起始日；起止相同为全天。
  每 30 秒/唤醒时匹配；手动充满优先于规则，但不优先于安全限制。
  不匹配或定位失效时回到基础上限，不保留失效地点规则。
- 定位：坐标仅存本机；拒绝、超过 5 分钟或精度范围超出地点区域时不匹配。
  只在启用的地点自动化需要时持续定位，并定期更新静止位置；编辑器可单次定位。

## 故障恢复

控制前取得跨开发/正式版本的排他锁，写入 root-only 恢复标记。
标记位于 `/Library/Application Support/VorssaintBatteryControl/active`，跨进程崩溃和重启保留。
充电写入后回读；部分写入失败时尝试恢复所有允许的 key，恢复成功才清除标记。
恢复失败保留后台持续重试。应用断连、退出或清醒期间超过 90 秒无心跳会恢复系统充电。
helper 在注册后由 launchd 保活；卸载先确认恢复，再注销 daemon，失败不删除应用。

默认不接管已被其他控制器设置的充电状态；识别到已有的暂停/放电状态时，
要求退出其他工具并通过“接管充电管理…”二次确认。接管前仍须通过状态校验并建立恢复记录。
不禁用系统优化充电的 CHWA 设置。
SMC 是非公开、机型相关接口；系统自身限制可能使“临时充满”无法立即开始充电。

## macOS Tahoe / M4 适配

按实际接口探测，不用芯片型号白名单。优先使用 CHTE（ui32，4 字节）控制充电，
CHIE（hex_，1 字节）控制外接电源；兼容旧 CH0B/CH0C/CH0I。
主动放电还要求 AC-W 物理插电检测，避免将放电产生的虚拟断电误判为拔掉充电器。
接口打开失败、读取失败、布局不符分别报告，不统一显示“机型不支持”。
更新主程序后若连接到旧版后台，会先确认旧后台完成恢复，再注销并重新注册；
若系统要求重新批准，则仍由用户在系统设置中批准。

M4 Pro（Mac16,8）、macOS 26.5 已完成只读探测：CHTE/CHIE/AC-W/ACLC 可读取，
识别为 Tahoe 后台。模拟测试覆盖 4 字节命令、写入顺序、异常回读和部分失败恢复。
这不等同于实机写入、主动放电或 MagSafe 灯效验收。
打包 helper 的 `--probe` 参数仅输出接口与当前状态，不修改硬件。

2026-09-03 开发版实机验证：已用原自签名证书安装，安装包签名与只读探测通过，
但新 daemon 注册后被系统以 `CODESIGNING / Launch Constraint Violation` 拦截，
launchd 随后报告 `EX_CONFIG`。因此后台控制尚未完成实机验收，不能视为充电控制已生效。
旧后台已安全退出，未接管原有暂停充电状态。下一步需处理后台注册/启动约束；
不得以关闭 AMFI、SIP 或取消 XPC 签名检查作为修复。

后续复验（同日）：通过签名应用的 `--reset-battery-registration` 注销旧服务，
等待 launchd 移除后首次注册仍返回 EPERM；待系统状态更新后再次注册成功。
新后台 PID 77330，launchd 为 running，应用显示“电池后台已连接 · Tahoe · CHTE”。
因此此前故障已通过重新注册恢复，无需关闭系统安全保护。
该恢复命令只允许在没有其他 Vorssaint 实例且恢复目录不存在时使用；
已有恢复目录或无法检查时拒绝操作，必须走正常认证恢复流程。
当前仍保留已有充电限制，等待用户退出其他充电工具并确认接管；尚未执行实机充放电验收。

## 验证

### 设置页后台诊断入口

设置页使用动态主按钮替代授权、重试、更新三个并列按钮，分别显示授权、连接及版本验证结果。
“检查并修复”重新建立认证连接并读取状态，不直接发送恢复充电命令；版本不匹配时沿用
确认恢复后才能更新的流程。未得到恢复确认时明确显示更新受阻，并保留后台与恢复记录。
返回 App 时刷新授权状态。报告包含 App build、预期/最近响应 codeHash、响应时间、错误和持久化日志。
报告中的最近响应不代表当前连接仍然有效。处理期间禁止重复操作，安全更新期间禁用设置页总开关。

该入口不绕过系统授权，也不保证能自动解决 launchd 启动约束或无响应后台；这些情况需查看报告继续排查。

连接连续失败后，每轮检查最多执行一次 launchd 启动诊断。只有读取成功、明确 `spawn failed` /
`78: EX_CONFIG`、无 PID，并且只读 SMC 检查为 automatic、再次检查仍无进程，才尝试注销
失效服务并注册新版。保留全部恢复记录，不强杀进程。其他状态拒绝该恢复路径。
注册完成后仍需协议、签名哈希握手及状态响应；注册成功不等于修复成功。
诊断报告包含系统启动状态、注册 build 和退出码。解析失败或权限不足均按未知状态处理。

### 签名漂移与管理员修复

运行中 helper 的签名使用进程身份检查，不通过磁盘上的新文件推断旧进程身份。确认不匹配时
提示使用原证书重新签名；权限不足、进程退出或验证失败仍标为未知，不误判签名不一致。

“强制修复…”仅经用户确认和系统管理员授权启动当前已签名 helper 的维护模式。
维护模式检查 enclosing App 签名，获取与正常控制共用的 root 所有权锁，并读回充电及电源
输入均为 automatic，才对本构建固定服务标识执行 launchctl bootout。不会接受任意 PID 或
服务名，不夺取现有锁，不删除恢复标记；未获得锁或硬件状态不安全时拒绝停止任何后台。
bootout 用于避免 KeepAlive 重新拉起旧服务；退出后再次检查旧 PID 与硬件状态。

App 收到明确维护成功标记后才注销旧注册、注册本包 helper；最终仍验证协议和 codeHash。
管理员授权取消、安全条件失败、停止/注销超时均保留错误，不报告成功。此流程不修改安装
脚本中的电池检查策略，也不放宽 XPC 的证书绑定。

验证范围：编译、签名、维护安全条件单元测试及现有电池回归测试；管理员停止服务路径需要
用户明确操作后的实机验收，不能用单元测试代替。后台持锁且无法恢复的情况仍拒绝强杀。

### 安装脚本与电池后台的边界

`./build.sh --dev --install`（构建并安装）和 `./build.sh --dev --install-existing`
（安装已有构建）只负责停止主程序、备份、复制 App 和签名验证。
按用户要求，已移除电池后台恢复确认、注销、等待进程退出、重新注册和握手验证。
电池 helper 的编译、打包和签名仍保留；App 内的诊断与安全更新逻辑不变。
旧 App 保留在安装输出列出的 `/Applications/.vorssaint-install-backup.*` 目录。
不会删除后台恢复日志，不会强杀无响应后台，不会绕过系统审批。

安装成功仅表示 App 文件安装和签名验证成功，不代表电池后台连接或充电控制已恢复。
脚本不再读取或生成 `build/.battery-install-<bundle-id>.pending`。

签名证书不可用时构建停止；应解锁原钥匙串，不自动创建或替换证书。
首次配置签名身份需显式执行 `Tools/setup-signing.sh`。
安装后如果旧后台仍运行或连接失败，应在 App 内查看诊断，不应将重复安装当作已修复。

运行 `bash Tools/test-battery-control.sh`：纯策略测试、模拟 SMC 写入/回读/恢复测试、
菜单与通知回归测试、helper 无硬件写入自检。`./build.sh --test` 也包含这些测试。

必须在受支持设备上、后台获准后另行验证：

1. 暂停/恢复和主动放电，比较 IOPS/电池电流与后台状态。
2. 应用退出、强制结束、helper 崩溃后的恢复及标记清除。
3. 实际合盖/唤醒两种睡眠策略，确认不会睡眠放电。
4. MagSafe 绿灯/闪烁；USB-C 无灯效不能当作失败。
5. 定位授权/拒绝、地点内外、跨午夜和时区变化。
6. 卸载路径确认后台已停止，任何恢复失败必须中止删除。

测试构建或模拟测试通过，不代表上述实机验收已完成。

实现参考：Apple 的 [电源睡眠通知说明](https://developer.apple.com/library/archive/qa/qa1340/_index.html)
与 [XPC 签名验证接口](https://developer.apple.com/documentation/foundation/nsxpclistener/setconnectioncodesigningrequirement(_:))。
SMC key/命令值核对了用户提供的 BatFi 公开仓库；没有导入其应用 UI 或资源。
Tahoe 接口协议核对了 [batt 的 SMC 实现](https://github.com/charlie0129/batt/tree/main/pkg/smc)，
本项目使用独立的 Swift 实现与模拟测试，未导入其源代码。
