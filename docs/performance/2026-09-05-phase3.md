# 第三批：共享剪贴板状态读取

本批集中完成第二批剩余清单中的剪贴板读取合并，保留前两批修改。

## 行为

- 历史、网址清理和延时清空共用每轮一次的异步 changeCount 查询。
- 剪贴板没有变化时，历史和网址清理不再单独访问剪贴板。
- 内容变化后仍在 GeneralPasteboardAccess 串行队列中重新读取；网址改写和清空仍执行原有的即时校验，避免旧状态覆盖新复制内容。
- 历史服务在无变化时仍结束来源归属检查窗口，保留排除应用的判断；内容读取时的隐藏/敏感类型检查保持不变。
- 只有延时清空订阅时每 1 秒检查，历史或网址清理启用时为 0.8 秒；全关闭则无定时器。
- 查询阻塞期间不新增查询，不通过超时重试堆积串行队列。旧查询完成后，只分发给发起时仍有效的订阅，新开启的功能不会收到旧观测。

## 可验证的收益与限制

三个消费者、剪贴板稳定时，每轮 changeCount 读取从三次减少为一次。100 轮测试验证只调用 100 次读取、分发 300 次结果。内容有变化时仍有独立的权威读取，因此不能把该比例解释为整机 CPU 或耗电下降比例。

本批不改变剪贴板功能的启用设置，未使用用户真实剪贴板进行改写或清空测试。浏览器 AX 事件监听、电池共用底层采样、截图稳定待选分析仍是后续独立项目。
