# 软件流量统计

网络 → 软件流量显示本次开机已记录的软件流量，默认按累计下载与上传合计排序，也可按累计下载、累计上传排序；列表只展示累计字节，不展示瞬时速度。默认显示前六项，支持查看全部以及展开子进程。已退出软件的累计值保留。

应用启动后使用单个持续运行的系统 nettop 流采集 TCP/UDP 的全部接口流量（包括连接本机 HTTP/SOCKS 代理的回环流量），每两秒采样。输出通过伪终端读取，避免普通管道缓冲导致低流量时迟迟没有更新。关闭面板、隐藏软件列表不会暂停采集。软件完全退出时停止；重新启动会恢复同一次开机已保存的数据，并标记记录中断。首次采集跳过已有累计计数，不补记启用前的流量。电脑重启后自动开始新一轮。开机与开始记录时间分别展示。

记录按应用路径聚合，无法识别应用的进程按名称保留；有归属的子进程归到负责应用。只保留子进程名称及其累计字节数，不保存连接地址、域名或内容。记录每十五秒原子写入本机 Application Support 下当前应用 bundle ID 目录的 app-traffic.json，正常退出时再次保存。意外崩溃最多可能丢失最近十五秒尚未保存的数据。

进程流量和网卡流量口径不同：局域网流量可能包含在内，代理及 VPN 转发可能重复归属，因此应用累计不能相加当作整机互联网流量。应用到本机代理的一段计入应用，代理转发的一段计入代理；不尝试把代理自身累计反向分摊给应用，也不做互联网/局域网分类。ChatGPT 内嵌 Codex 的发行版显示为 ChatGPT / Codex 共享应用合计，展开查看子进程，不能将共享 Service 的字节精确拆分为单个 Codex 会话。旧记录保留，界面标明开始包含本机代理连接的时间，之前漏记的数据无法补回。极短连接或进程可能漏采，归属失败时保留系统提供的进程名。不是计费审计工具。

采集失败显示错误，每十五秒重试；超过二十秒没有新样本清零当前速度并标记中断，超过三十秒尝试重启采集。恢复时丢弃新采集器的首个已有累计段。未开启登录启动时，用户登录至应用启动之间的流量不在记录内。

验证：`zsh Tools/test-app-traffic.sh`，覆盖累计与子进程合并、同次开机恢复、重启分段、损坏记录以及首次计数丢弃和解析器重置。

开发版可通过 `open -a "/Applications/Vorssaint (Developer).app" --args --network-preview` 打开使用同一服务的网络验收窗口（需在启动时传参）。正常启动不显示该窗口。

`zsh Tools/test-app-traffic.sh --live` 额外运行十秒真实 nettop 流及 2.5 MiB 本机回环传输，检查两秒采样是否及时输出，以及 CPU 时间是否低于一秒，防止管道缓冲和输入 EOF 忙循环回归。该检查仅在 127.0.0.1 上传输测试数据，不连接外网，并验证数据按发起进程计入。

设置 → 网络信息顶部的「软件流量统计」按钮直接打开同一份实时流量榜，支持排序、查看全部和展开子进程。关闭统计窗口不影响后台采集。

## 软件流量与链路

原「软件流量统计」入口已替换为「软件流量与链路」。设置 → 网络信息可打开左右分栏窗口：左侧按累计合计、下载、上传或当前速度排序；右侧查看已选软件累计、实时速度、当前连接路径、代理报告目标和累计子进程。菜单栏简表保留「查看网络链路」入口。

链路窗口打开时每五秒通过有超时和输出上限的 lsof 字段模式扫描当前 TCP 端点与监听进程。匹配精确反向端点时才标记「已确认本机连接」；通过监听地址区分本机入站和出站。关闭窗口停止连接扫描，后台累计流量继续。连接快照仅保存在内存，不补记过去的路径。UDP、短连接、权限受限进程和非回环本机地址可能不完整；计数以进程端点为单位，同一条本机连接两端会各有一项。

自有代理目标由现有 ProxyTelemetry 读取，只在数据新鲜且代理报告的完整应用路径匹配时展示。这里只按应用归属分组，没有声称每条目标已与某个本机 TCP 端点一一关联。代理活动连接字节数不混入软件开机累计。FlClash 没有提供控制接口时只展示可确认的本机连接，其他下游留为待关联，不自动改变代理配置或拼接请求因果关系。

验证：`zsh Tools/test-network-chain.sh` 覆盖 IPv4/IPv6、TCP 与 UDP 区分、监听方向、反向端点匹配、缺失对端、重复记录及应用路径识别。累计记录继续由 `zsh Tools/test-app-traffic.sh` 验证。

### 逐目标连接流量

目标列表逐行显示路径、下载、上传、合计和采样速度，默认按当前连接累计合计降序。通过有限次 nettop 连接级采样（不使用 -P、不使用增量输出），以 PID、本地端点和远端端点精确匹配 lsof 连接；不借用进程总流量或反向对端流量。IPv6 地址端口格式统一后再匹配。缺失计数显示「未采集」；首次样本、计数回退和超过二十秒的间隔不产生速度。

系统连接计数是当前存活连接已有的累计，可能早于窗口打开；不是自开机保存的逐目标历史。连接关闭后从目标列表移除，软件后台累计继续保留。此扫描仅在链路窗口打开时运行，不保存目标地址历史。

自有代理解析保留 sourceIP/sourcePort；仅当 TCP 来源端点和本机代理监听端口唯一匹配时，将目标域名、该目标的代理累计和代理报告路径关联到这一行。没有来源信息、不唯一、数据过期或不同代理端口时不关联。FlClash 未开放接口时显示「软件 → FlClash → 下游待关联」，不会将代理节点 IP 冒认为最终访问域名。

`zsh Tools/test-network-chain.sh --live` 会只读核对真实 TCP 端点与 nettop 计数；离线测试覆盖逐连接独立数值、IPv6、监听行排除、缺失／非法计数、计数回退、采样间隔和代理来源端点精确匹配。

### 采集器退出监管

常驻 nettop 由同一签名程序的 `--app-traffic-worker` 内部模式监管，先于 GUI 和启动服务进入。GUI 与监管进程用专用管道维持存活关联；管道 EOF、父 PID 变化、SIGTERM、SIGINT 或 SIGHUP 都会触发清理。监管进程先终止并回收自己创建的 nettop，最多等待半秒后强制结束，再关闭 PTY，避免终端先断开导致 nettop 在 EOF 上忙循环。父 GUI 即使被 SIGKILL，监管进程仍能独立完成清理，不依赖 AppDelegate 退出回调。新增监管进程为当前用户进程，不安装常驻系统服务。

`zsh Tools/test-traffic-worker.sh` 是六秒左右的真实采集器生命周期测试，覆盖父管道关闭、监管进程终止和父进程被强杀；仅清理本测试创建的 PID，不对系统其他 nettop 批量操作。
